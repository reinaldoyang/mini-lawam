# DINOv3 Setup Notes — Local Conversion vs Official HuggingFace

Short record of how the DINOv3 ViT-B/16 encoder was set up for the LAM (Stage 1),
and how to revert to the official HuggingFace version once gated access is approved.

## Why this exists

`facebook/dinov3-vitb16-pretrain-lvd1689m` is a **gated** HF repo (requires approval).
The initial `hf download` only pulled the raw torch-hub `.pth` before hitting
`Access denied`, so the HF-format files the LAM loader needs
(`config.json`, `model.safetensors`, `preprocessor_config.json`) were missing.

The LAM loads DINOv3 via `AutoModel.from_pretrained(vision_model_id, ...)`
(`latent_action_model/core/vjepa_encoder.py`), which needs the HF format — a bare
`.pth` is not usable on that path.

**Fix applied:** converted the local `.pth` (which contains the correct, complete
weights) into HF format offline, using HuggingFace's own conversion logic. No
approval, no retraining, no DINOv2 substitution.

## Current state (LOCAL CONVERTED version is ACTIVE)

- **Converted HF files live in:** `weights/dinov3-vitb16-pretrain-lvd1689m/`
  - `config.json`, `model.safetensors`, `preprocessor_config.json`  ← generated by conversion
  - `dinov3_vitb16_pretrain_lvd1689m-73cec8be.pth`                    ← original gated download (kept)
  - `LICENSE.md`, `README.md`
- **Active pointer:** `latent_action_model/logs/dino_large_vae/lam_release/dino_large_vae.yaml`
  line 3: `vision_model_id: weights/dinov3-vitb16-pretrain-lvd1689m`
- **Conversion scripts:** `scripts/dinov3_convert/`
  - `convert.py`        — official HF script (fetched from transformers `main`)
  - `convert_local.py`  — adapter: loads the local `.pth`, keeps HF's reference-output
    validation, drops the `model.` key prefix (needed for `transformers 5.2.0`)

### Validation that was passed

Conversion loaded `strict=True` and the forward pass on the canonical COCO image
matched HF's published reference within `atol=1e-3`:

```
cls actual  : [1.034838, -0.180611, -0.340829, -0.066643, -0.011384]
cls expected: [1.034643, -0.180609, -0.341018, -0.066376, -0.011383]
```

The full LAM then loaded end-to-end and produced valid outputs
(z `(1,1,32)`, subgoal `(1,1,256,768)`, finite).

The local conversion is bit-exact with the official weights, so switching back
does **not** change any results and needs no re-validation or retraining.
The LAM checkpoint (`pytorch_model.pt`) does not store DINOv3 weights — it rebuilds
the encoder from `vision_model_id` each load — so it is unaffected either way.

## How to REVERT to the official HuggingFace version

First, get approved: https://huggingface.co/facebook/dinov3-vitb16-pretrain-lvd1689m
→ "Agree and access repository" (logged in as the account whose token is on this machine).

### Option A — keep local dir, refresh with official files (RECOMMENDED)

Leave the YAML pointer as-is and re-download into the same folder. This overwrites
`config.json` / `model.safetensors` with Meta's official bytes; stays offline-friendly
afterward; no HF token needed at load time.

```bash
cd /home/iclu200/reinaldoyang/LaWAM
hf download facebook/dinov3-vitb16-pretrain-lvd1689m \
  --local-dir weights/dinov3-vitb16-pretrain-lvd1689m
```

(Optional cleanliness) remove the local-conversion artifacts once official files are in:
```bash
# the scripts can be deleted; they are only needed to (re)generate the local version
rm -rf scripts/dinov3_convert
```

### Option B — load directly from the Hub

Edit `latent_action_model/logs/dino_large_vae/lam_release/dino_large_vae.yaml` line 3:

```yaml
# from:
  vision_model_id: weights/dinov3-vitb16-pretrain-lvd1689m
# to:
  vision_model_id: facebook/dinov3-vitb16-pretrain-lvd1689m
```

Requires at load time: network access **and** an approved HF token
(`export HF_TOKEN=...` or `hf auth login`). More fragile on training/eval nodes.
